01 / ArchitectureJava · Flutter

1day per new form

Configuration over code

Problem
Every new state or programme meant new code and a new release.
My call
Stop hand-coding forms. I designed a configurator and renderer so forms, rules and workflows became configuration.
Result
A new form in a day and a new state in a week. The platform scaled to 12 deployments.
  • System design
  • Rule engine
  • Spring Boot
  • Flutter
02 / Applied AIWhisper · Qwen · Gemini

10×faster data entry

Voice-first data entry

Problem
Health workers spent 3–4 minutes typing each form on small screens, often without a network.
My call
Let them speak instead. Whisper for speech-to-text, an on-device Qwen model offline, and Gemini when online.
Result
Form entry dropped to about 20 seconds.
  • Speech-to-text
  • On-device LLM
  • Offline
03 / PerformancePostgreSQL · SQLite

30×faster sync

Offline-first sync

Problem

My call
Redesigned the sync strategy and tuned the heaviest queries, on top of offline data models with conflict resolution.
Result
Sync in about 10 seconds for the largest deployment, 220 million citizens.
  • Conflict resolution
  • Bloc
  • Query tuning

04 How I work

Four rules I lead by.

  1. 01

    Build for the worst network, not the best.

    If it works offline on a cheap phone in a village, it works everywhere.

  2. 02

    When a problem repeats, configure it.

    The third time I write the same code, I build the tool that writes it instead.

  3. 03

    Grow owners, not followers.

    A team is ready when it ships without me. I've grown more than ten engineers into implementation owners.

  4. 04

    A deadline is a design constraint.

    Government rollouts don't move. I plan scope and architecture around the date, then hit it.
